# Frontend source layout

`main.tsx` mounts React. Application composition lives in `app`, product code
is grouped by feature, and code used across features lives in `shared`.

```text
src/
  main.tsx
  app/
    App.tsx               Authentication shell and application providers
    MainNavigation.tsx    Top-level navigation
    router.tsx            Routes and lazy page imports
    styles/               Global and vendor styles
  features/
    account/              Settings, notifications, and the user's jobs
    admin/                Administration, service health, and client log views
    annotation/           Annotation workspace, image context, and annotator
      sets/               Annotation-set selection, editing, and category matching
    chain-viewer/         Chain viewing, sharing, and share administration
    homography/           Image registration and homography tasks
    images/               Image viewing, navigation, and mask editing
    individual-id/        Individual identification and pair matching
    info-tags/            Information-tag annotation and workflow statistics
    organizations/        Organization registration, membership, and permissions
    results/              Result generation, maps, sharing, and snapshots
    review/               Annotation review and quality-control tasks
    statistics/           User and workflow statistics pages
    surveys/              Survey creation, editing, configuration, and launches
    tasks/                Task queues, buffering, completion, and task state
    testing/              Test configuration, cadence, execution, and results
    uploads/              Upload UI, orchestration, persistence, and workers
  shared/
    api/                  Data clients, schema adapters, GraphQL, and pagination
    auth/                 Session context and authentication helpers
    components/           Reusable controls, tables, modals, and progress UI
    data/                 Shared query hooks, cache operations, and query client
    hooks/                Shared lifecycle, activity, and progress hooks
    imaging/              Map viewer, image sources, tiles, and geometry helpers
    logging/              Client logging and action logging
    routing/              Dialog routing, guards, and organization route helpers
    stores/               Shared progress state
    types/                Shared frontend types and third-party declarations
    utils/                Focused cache, subscription, hotkey, and shapefile helpers
    workflows/            Shared workflow registry, events, and recording
```

## Where new code belongs

- Start with the feature that owns the behavior. Keep its components, hooks,
  types, helpers, tests, and styles together. Add subdirectories when a feature
  has a distinct area, as in `annotation/sets` or `uploads/core`.
- Put code in `shared` when multiple features use it. Keep helpers in modules
  named for their responsibility; avoid a catch-all `utils.tsx` or barrel that
  eagerly loads unrelated features.
- Keep tests in the repository-level `tests/` folder, mirroring source paths
  under `tests/src/` and `tests/amplify/`. See [the test guide](../tests/README.md).
  Keep component styles beside their components; global styles belong in `app/styles`.
- Import modules directly using relative paths. The router retains dynamic
  imports so feature pages continue to load lazily.
- Keep generated backend types in `amplify/shared`. Frontend clients and schema
  adapters in `shared/api` reference them; do not copy generated definitions
  into feature folders.

The optional, git-ignored developer page belongs at `app/DevActions.tsx` and must
export `DevActions`. The router discovers it only when that file is present.
Existing local copies should be moved from `src/DevActions.tsx` and their relative
imports updated.

## Validation

Run from the repository root:

```sh
npm test
npm run typecheck
npm run build
npm run lint
```

The test command discovers tests recursively under `tests/`. The build regenerates
the backend type definitions, checks frontend and Vite configuration types, and
bundles the frontend using the existing local
`amplify_outputs.json` configuration.

The standalone backend check (`npx tsc --project amplify/tsconfig.json --noEmit`)
also needs the Amplify-generated environment declarations in `.amplify/generated/env`.
Those declarations are generated by Amplify and are not checked into the repository.
